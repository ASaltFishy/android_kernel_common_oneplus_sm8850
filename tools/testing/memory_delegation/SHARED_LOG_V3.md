# Shared Arena ABI v3: kernel-owned normal slot recycling

2026-10-24. Supersedes the normal receipt retention rules in SHARED_LOG_V2.md. The historical `shared_log_v2.*` and runner filenames now compile and test v3.

- `normal.reserved` is the release-published producer tail, serialized by the process-shared Arena Mutex. `normal.head` is the kernel release-published contiguous **successful** prefix. Producer capacity is `tail - head < capacity`. The kernel no longer writes success results into normal slots. There is no normal `completed` or user `reclaimed` cursor and no normal success receipt scan.
- Consumer snapshots remote's contiguous ready prefix first, then normal tail; consumes the normal snapshot before the remote snapshot. A migrated normal producer can run concurrently with the owner CPU consumer, so release/acquire publication is still mandatory. The kernel does not clear record bytes; successful head advancement releases slots for overwrite only after committed truth is published.
- The first normal failure is copied to `normal_error` outside reusable slots, then STOPPED is release-published. Normal head never crosses that failure. Both new normal and remote publication reject STOPPED. Corrupt queue/publication similarly stops conservatively. Retained errors and unfinished requests cannot be overwritten or interpreted as success.
- A local FREE published while still on the owner CPU immediately updates the shared free indexes as before. If its holder migrated, its immutable Pending descriptor stores ticket+1 and joins an ArenaMutex-protected exceptional pending list. Reaping runs only on owner-CPU entry, under the same Mutex; head >= saved ticket proves that FREE succeeded because head cannot cross an error. The descriptor cannot split/merge/reuse while Pending. No normal slot contents are consulted after head publication.
- The remote ring retains reserved/completed/reclaimed and per-slot results. Remote FREE producers still touch only log storage. Owner user code validates lease/session/generation/range and result before publishing the block free and releasing its receipt slot. Reservation holes, dead producers, and abandoned Mutex owners retain their conservative no-recovery behavior.
- Head/remote completion still do not prove all PTE/TLB revocation is finished. Existing task_work/PTE synchronization is preserved.
- Read-only capability query: `prctl(74, 0, SHARED_RINGS, 0, MD_SHARED_LOG_QUERY)` returns 3 on a matching kernel. Old kernels reject it. Registration also checks version 3 and the new log layout. Metadata/broker version is 8. Never reuse a v7 backing or install these binaries against the current v2 phone kernel.

Validation in this change is compilation only; protocol tests were updated but not executed at the user's request. A new kernel build is not permission or evidence to flash: preserve the current phone and require the normal KABI, matching-module and boot checks before any later deployment.
